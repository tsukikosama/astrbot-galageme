# AstrBot 关系成长与记忆插件设计文档

版本：v0.1  
状态：开发前设计稿  
日期：2026-10-27  
最后更新：2026-10-29（新增 5.6 用户查询好感度、5.7 数值等级、5.8 每日变化上限，并同步第3、5.4、7.5、11、13、15节）  
建议项目名：`astrbot_plugin_relationship_memory`  
使用场景：QQ群自然对话

## 1. 项目目标

为 AstrBot 增加类似 Galgame 的持续关系体验：同一个机器人保留初始人设，通过与不同用户的日常对话，逐渐发展出不同的关系、相处方式和共同记忆，并在适当时机主动 @ 用户交流。

用户正常与机器人聊天即可参与，不要求签到、赠送道具或输入功能指令。

核心循环：

```text
自然对话 → 积累经历 → 更新关系与相处方式
    ↑                         ↓
用户回应 ← 个性化回复或主动互动 ← 检索相关记忆
```

本插件是关系与记忆增强层，不替代 AstrBot 的平台接入、基础人设和主要对话流程。

## 2. 已确定的设计原则

1. 初始人设是稳定起点：不擅自改变角色身份、基础性格、价值观和硬性边界。
2. 不写死关系路线：不预设“高好感一定温柔”“关系亲近一定恋爱”。
3. 每个人独立发展：根据实际互动形成不同的关系，而不是只换称呼的同一套回复。
4. 数值与经历共同生效：数值描述趋势，记忆解释原因，相处描述指导表达。
5. 关系缓慢变化：普通问答可以没有变化；重要事件有持续影响。
6. 主动互动有动机：先有相关话题、约定或关系动机，再按概率判断是否联系。
7. 事实和感受分开：角色可以失落、误会，但不能把这些感受保存为用户事实。
8. 用户可纠正、删除记忆，也可关闭主动联系。
9. 低好感不降低正常回答质量；未回复、正常纠错和表达不同意见不自动扣分。

## 3. 第一版范围

### 3.1 包含

- QQ群内自然对话识别与用户隔离。
- 好感、信任、熟悉、亲近四个关系维度。
- 独立的短期情绪状态。
- 根据经历更新的相处描述。
- 用户事实、偏好、共同事件和关系记忆。
- 每日记忆整理、去重、更新与失败补偿。
- 约定及待跟进事件。
- 基于动机与概率的主动 @ 消息。
- 用户查询本人好感度（见 5.6）。
- 四个维度的数值等级换算与展示（见 5.7）。
- 可配置的每日变化上限，0 表示不限制（见 5.8）。
- 自然语言查询、纠正、删除及暂停记忆。
- 管理员查看、纠错、暂停、重置与审计。

### 3.2 暂不包含

- 固定恋爱路线、强制告白或排他关系。
- 商店、送礼、签到刷分和数值排行榜。
- 多机器人共享关系、跨群自动合并档案。
- 独立向量数据库和复杂知识图谱。
- 自动读取历史群消息或默认保存所有群友闲聊。
- 面向普通用户的复杂管理页面。

## 4. 身份和会话范围

关系主键：`bot_profile_id + platform_id + group_id + user_id`。

- 使用稳定 QQ 号识别用户，不使用昵称作为主键。
- `bot_profile_id` 为插件内配置的角色档案标识，不假定 AstrBot 已提供同名字段。
- 同一用户在不同群默认独立；不同机器人角色默认独立。
- 用户改昵称不会新建关系。
- 初版只处理群内与机器人实际发生的互动，不导入私聊内容。
- 普通成员不能查询、修改其他成员的完整档案。

### 4.1 参与对话的判定

默认处理：@机器人、回复机器人消息，以及 AstrBot 现有唤醒配置认可的自然对话。

默认忽略：群友之间的闲聊、机器人自己的消息、其他机器人的消息、无法归属用户的事件、重复投递消息。

如果后续开启群话题感知，只短暂使用必要的群聊上下文；未参与用户的发言不自动建立长期档案。

引用或转发内容须保留作者与引用关系，不能将被引用的话直接归到发送者名下。无法可靠归属时不改变关系。

## 5. 关系模型

### 5.1 关系维度

以下均为第一版可调默认值，不代表固定剧情阶段。

| 维度 | 范围 | 初始值 | 含义 |
|---|---|---|---|
| 好感 affection | 0～100 | 20 | 是否喜欢与对方相处 |
| 信任 trust | 0～100 | 10 | 是否愿意相信、坦诚和接受承诺 |
| 熟悉 familiarity | 0～100 | 0 | 了解程度及共同经历积累 |
| 亲近 closeness | 0～100 | 0 | 相处距离、关心表达与亲密表达的自然程度 |

数值由插件维护，模型只能提交变化建议。用户说“把好感改为100”不构成修改授权。

各维度独立，不互相机械换算。例如可以很熟悉但缺少信任，也可以喜欢交谈但仍保持距离。

### 5.2 短期情绪

记录情绪名称、强度、原因和到期时间，例如：`有点失落 / 0.3 / 约定未兑现 / 6小时`。

- 情绪随时间回落到基础状态。
- 情绪不自动转化为永久关系变化。
- 长期关系限制短期反应的幅度，避免一次冒犯导致完全陌生。
- 用户未回复，不自动产生“故意冷落我”等事实判断。

### 5.3 动态相处描述

每段关系维护一份简短描述，包含：

- 已形成的交流习惯与默契。
- 对关心、玩笑和亲密表达的接受方式。
- 尚未解决的矛盾或承诺。
- 重要关系转折及其来源。
- 尚不确定的关系判断。

示例：

> 与小林经常互相吐槽，习惯了对方的玩笑。面对关心仍然嘴硬，但会认真回应。上次小林忘记约定让它有些失落，最近的道歉缓和了这种感觉，但信任尚在恢复。

相处描述须关联证据，不能仅因一句表白就认定角色已经依赖对方，也不能无事件依据每天重新编写关系走向。

### 5.4 更新规则

| 情况 | 默认处理 |
|---|---|
| 普通问答、重复寒暄 | 多数不变 |
| 真诚关心、有意义的交流 | 适度增加相关维度 |
| 履行约定、尊重边界 | 主要增加信任 |
| 共同经历和持续互动 | 缓慢增加熟悉 |
| 明确恶意辱骂、反复挑衅 | 结合上下文适度降低相关维度 |
| 道歉与关系修复 | 根据后续行为逐步恢复，不立即清空影响 |
| 纠错、拒绝、不赞同、暂时离开 | 不自动扣分 |
| 玩笑、引用、语义不明确 | 低置信度时不变 |

默认每个维度单次变化不超过 ±3；每日累计变化按 5.8 的可配置上限执行（默认增加不超过8、降低不超过10）。熟悉度主要随有效经历缓慢增长，通常不因争执下降；纠错或删除错误经历时可重新计算。

加入重复内容去重、互动冷却和当日收益递减。未上线不扣分。重要事件必须记录来源，不能通过重复请求刷成多个事件。

### 5.5 更新顺序

1. 检查身份、去重和功能开关。
2. 处理明确的记忆控制意图和本人数值查询（见 5.6）。
3. 根据本轮输入和近期上下文提出关系变化建议。
4. 插件校验置信度、数值范围、冷却和日累计限制。
5. 生成本轮使用的临时关系状态，注入回复上下文。
6. 对话完成后提交一次关系变化和互动记录；回复失败则丢弃临时变化。

一轮对话中的多次模型调用、工具调用和分段输出只能结算一次。后续每日整理不得重复结算同一事件。

### 5.6 用户查询好感度

用户可主动查看自己当前的关系数值，不需要管理员身份，也不需要签到或道具。

**触发方式**：在已启用的群里 @机器人（或已唤醒的对话中）发送明确的查询句，例如“查看好感度”“我的好感度”“好感度多少”。

**判定规则**

| 规则 | 说明 |
|---|---|
| 整句匹配 | 只有整句都在询问本人数值时接管；“把好感度改成100”“好感度怎么提升”“查看他的好感度”交给模型正常回复 |
| 本人范围 | 只返回发送者本人在当前群、当前角色档案下的数值，不返回他人数值 |
| 只读 | 不调用模型、不改任何数值、不写入记忆、不生成互动记录、不结算本轮关系 |
| 不影响其他模块 | 不刷新主动联系冷却，不占用群级主动预算，不触发主动消息 |
| 开关可关 | 关闭后该句按普通聊天处理，模型不得编造或估算数值 |

**返回内容**：默认给出好感度数值（0～100）、对应等级（见 5.7）和一句自然语言相处描述；可配置为同时展示好感、信任、熟悉、亲近四维，或只返回描述不显示数字（此时仍给出等级名称）。从未互动过的新档案应说明这是初始值，而不是虚构相处经历。

示例：

```
当前好感度：42 / 100（Lv.3 熟悉）
对你印象不错，还在慢慢熟悉。
这是我们到现在为止的相处感觉，正常聊天就会慢慢变化，不需要特意刷。
```

**可见性**：回复发生在群内，其他群成员可以看到。这是用户主动查询的预期结果，插件不做私密化承诺；敏感内容仍按 7.2 处理，不在群内展开。

**与管理员查看的区别**：用户查询只返回本人数值、等级和一句描述；管理员“查看”仍可看到四维数值与等级、记忆与联系开关、当日已用额度、最近变更原因，用于纠错和排查。

### 5.7 数值等级

四个维度共用同一套量化等级，把 0～100 的数值换算成可理解的档位，方便用户查看和运营观察，不额外存储字段、不参与计算。

| 等级 | 名称 | 数值区间 | 展示描述 |
|---|---|---|---|
| Lv.1 | 陌生 | 0～24 | 还不太熟，先多聊聊吧 |
| Lv.2 | 认识 | 25～39 | 刚认识不久，还在找彼此舒服的相处方式 |
| Lv.3 | 熟悉 | 40～54 | 对你印象不错，还在慢慢熟悉 |
| Lv.4 | 朋友 | 55～69 | 和你聊天是件愉快的事 |
| Lv.5 | 亲密 | 70～84 | 挺喜欢和你聊天的 |
| Lv.6 | 羁绊 | 85～100 | 和你相处很放松，也很愿意继续聊下去 |

规则：

- 等级按区间下界判定，例如 40 分即进入 Lv.3；超出范围先夹到 0～100 再换算，不产生 Lv.0 或 Lv.7。
- 等级只是数值的只读标签，不是任务、称号、权限或剧情阶段，也不作为解锁条件。
- 等级不改变帮助质量：低等级同样正常回复、不冷落、不责备；高等级也不代表可以越过用户边界。
- 等级名称与描述随数值变化自动更新，不做跨天缓存，也不写入长期记忆。
- 等级同时注入关系上下文供模型参考；模型不得据此宣称“已达某阶段”“解锁某关系”，也不得自行换算或推算数值。
- 用户查询本人数值（5.6）、管理员查看（第 12 节）均展示等级；普通聊天不主动提及。
- 管理页同样展示等级：用户列表在好感数值旁显示等级名称，详情页每个维度显示“Lv.3 熟悉”标签和该档位的展示描述。等级由接口按当前数值现算，仅用于展示，不落库。

### 5.8 每日变化上限

每日累计变化按“每个用户、每个自然日（北京时间）、每个维度”分别记账，防止短时刷分或恶意刷低。

| 配置项 | 默认 | 作用范围 | 0 的含义 |
|---|---|---|---|
| daily_affection_gain | 8 | 好感每日增加 | 不限制 |
| daily_affection_loss | 10 | 好感每日下降 | 不限制 |
| daily_dimension_gain | 8 | 信任/熟悉/亲近每日增加 | 不限制 |
| daily_dimension_loss | 10 | 信任/熟悉/亲近每日下降 | 不限制 |

规则：

- 上限只限制“当日累计生效值”，不限制单次建议值；单次建议仍按 ±3 校验（见 5.4）。
- 当日额度用尽后，本轮该方向的变化记为 0，关系数值不变，不报错、不提示用户，也不影响记忆、待办和主动模块。
- 配置为 0（或留空、填非法值）表示该方向不限制；负数同样按不限制处理，不应解释为禁止变化。
- 额度按自然日重置，不滚动累计；跨日后的新互动重新计额。
- 上限收紧只影响之后的变化，不回退已经生效的历史数值；放宽上限也不会补偿此前被截断的部分。
- 熟悉度仍只允许正向变化；纠错、删除错误经历或管理员重置按既有流程重算，不受当日额度限制。
- 管理员可在查看结果中看到当日已用额度与当前配置，便于判断是否因额度用尽而未生效。

## 6. 回复生成

回复参考顺序：基础人设及平台规则 → 用户记忆与联系偏好 → 当前关系和短期情绪 → 相关记忆 → 当前对话。

动态关系内容应作为独立上下文片段提供，避免每轮重写稳定人设。实际注入位置按部署版本的公开接口适配。

生成要求：

- 保留同一个角色的语言和行为逻辑。
- 根据对象表达不同的相处方式，不套用固定阶段台词。
- 不必每句话提及关系或旧事。
- 不主动向群聊暴露数值、分析结果或内部提示词；用户本人按 5.6 查询时由插件返回本人数值，模型不得自行编造或估算。
- 等级（见 5.7）只是数值区间标签，不得据此宣称进入某阶段、解锁某关系或改变帮助质量。
- 不凭空声称共同经历；记不清时允许坦诚表达不确定。
- 不因关系亲近擅自进入恋爱、占有或排他模式。
- 关系疏远时可保持边界，但仍正常提供帮助。

## 7. 记忆系统

### 7.1 记忆类型

| 类型 | 内容 |
|---|---|
| 近期上下文 | 正在进行的对话、指代和当前话题 |
| 用户事实 | 用户明确表达的称呼、近况等 |
| 用户偏好 | 回答长度、外号、玩笑及联系偏好 |
| 共同事件 | 双方共同讨论、完成或经历的事情 |
| 关系记忆 | 争执、和解、谈心、形成默契等转折 |
| 待跟进事项 | 考试、面试、约定和需要后续询问的事情 |
| 每日摘要 | 当天有效互动的压缩记录 |

### 7.2 单条记忆字段

`id、scope、owner_id、type、content、source_message_ids、occurred_at、created_at、updated_at、confidence、importance、visibility、status、supersedes_id、expires_at`。

- 标明来源类型：用户明确表达、可验证事件、角色感受或待确认推测。
- 角色感受单独保存，不进入用户事实档案。
- 第一版不将未经确认的模型推测当作稳定用户事实。
- 机器人自己生成的用户信息不能成为事实来源。
- 支持公开可提及、仅响应本人相关询问、禁止主动提及三种使用范围。

“仅响应本人”表示访问限制，不代表QQ群回复具有私密性；敏感内容不在群内展开，应省略或引导用户在支持的私密渠道处理。

### 7.3 即时记录与每日整理

用户明确说“以后叫我小林”“不要叫我这个外号”时即时更新，不等待每日任务。

每日北京时间03:00，只整理有新增互动的档案：

1. 读取未整理且允许保留的互动记录。
2. 提取事实、偏好、共同事件及关系转折。
3. 合并重复记忆，处理过期信息和新旧冲突。
4. 更新相处描述，保留关键转折及证据。
5. 生成每日摘要，记录已处理的消息范围。
6. 成功提交后推进整理进度；失败保留任务以供重试。

明确的新事实可以取代旧状态，但保留合理的时间线。例如“准备面试”更新为历史事件，“已经入职”成为当前状态。矛盾不明确时标记待确认，不直接覆盖。

支持离线补跑、分批处理和幂等执行；只有新增数据才产生整理请求。

### 7.4 检索与容量

第一版使用 SQLite、关键词、时间和重要度排序。每轮默认取最多5条相关记忆，并设置动态上下文长度上限。

无关记忆不注入；旧的短期状态逐步过期；重要承诺和关系转折长期保留，直到用户删除或管理员纠错。

原始互动记录建议默认保留30天。摘要、长期记忆和备份的保留周期分别配置；关闭记忆后不再保存新的长期内容。

### 7.5 自然语言管理

| 用户表达 | 行为 |
|---|---|
| “你记得我什么” | 返回适合在群里展示的本人摘要 |
| “查看好感度” | 返回本人当前好感度及一句相处描述；只读，不改数值（见 5.6） |
| “刚才是开玩笑的” | 标记相关内容不可当作事实，修正衍生记忆 |
| “我现在已经换工作了” | 更新当前状态，保留必要时间线 |
| “这件事别在群里提” | 修改可见性，禁止在本群主动提及 |
| “忘掉我上次说的地址” | 删除或清理对应记录及衍生摘要 |
| “以后别记我的聊天” | 停止新增长期记忆；默认同时暂停依赖记忆的主动联系 |
| “删掉关于我的所有记忆” | 按明确范围清理；未明确要求重置关系数值时保留数值并告知范围 |

简单明确的请求直接执行并反馈；指代不清时只追问必要范围。不能只由模型口头答应，必须有实际执行结果。

删除需覆盖原始记录、记忆、每日摘要、相处描述和待跟进事项，并使缓存失效。保留不含被删正文的删除标记或处理边界，防止历史重试恢复内容。备份无法即时修改时，按保留策略到期清除；恢复后必须重放删除标记。

## 8. 主动互动

### 8.1 触发来源

- 待跟进事件进入合适时间窗口。
- 出现与用户偏好或共同经历有关的群话题；该能力单独开关。
- 有尚未完成的约定。
- 关系形成的主动联系倾向，在适当间隔后提供轻量问候动机。

单纯随机抽到用户但没有合适内容时，不发送。

### 8.2 概率设计

默认候选检查周期15分钟，每次只处理有效互动机会。

```text
p = clamp(基础概率 × 角色主动倾向 × 双方关系倾向
          × 动机强度 × 场合系数 × 联系反馈系数, 0, 0.8)
```

建议基础概率0.10；各系数由可配置规则计算。模型可提出动机和解释，不能绕过硬性限制直接发送。

概率针对唯一机会计算，建议键为 `用户 + 动机事件 + 时间窗口`。抽取结果持久化，同一机会不反复重抽；有时效的机会过期后关闭。

好感度不直接等于联系频率。保留角色主动倾向，再依据双方已有习惯调整；不因群成员数量多而逐人无限抽签，先对有限候选排序，再执行群级预算。

### 8.3 硬性限制

| 配置 | 默认值 |
|---|---|
| 每群每天主动消息上限 | 3条 |
| 每用户每天主动联系上限 | 1次 |
| 同用户主动联系冷却 | 12小时 |
| 同群主动消息最小间隔 | 60分钟 |
| 安静时段 | 北京时间23:00～09:00 |
| 主动联系范围 | 已启用群中已有有效互动的用户 |

未回应不追问、不扣分；多次未回应逐步降低联系倾向，回复后再结合偏好恢复。明确拒绝优先于任何概率。群已禁用、用户已退出、发送权限不足或身份无法确认时不发送。

### 8.4 消息生成与发送

选择候选 → 检查偏好、预算和冷却 → 概率判定 → 检索公开可用记忆 → 生成内容 → 检查相关性、重复与可见性 → 再次检查权限并预占额度 → 发送真正的QQ @消息组件 → 记录结果。

主动发送本身不增加好感度。用户后续回复再进入正常互动流程。不能仅输出“@昵称”文本冒充真正的@。

发送使用待发送记录和唯一任务ID。明确失败可退还预占额度；超时且无法确认是否送达时记录为未知状态，不盲目重发，避免重复打扰。

### 8.5 约定和准确提醒

概率问候与准时提醒分开。只有真正保存了定时任务并能执行，才能答应“明早8点提醒我”。初版未实现准确提醒时，不承诺准点发送。

相对日期按北京时间和原消息时间解析，记录原表达及标准时间。存在歧义时确认，不猜测重要日期。

## 9. 数据与模块设计

### 9.1 建议数据表

| 表 | 职责 |
|---|---|
| profiles | 身份、参与状态、记忆及联系偏好 |
| relationships | 四维数值、情绪、相处描述、版本号 |
| relationship_events | 变化建议、实际变化、原因、来源、撤销状态 |
| interactions | 消息归属、有效对话、完成状态、保留期限 |
| memories | 结构化长期记忆及来源 |
| memory_sources | 记忆与消息/事件的多对多来源关系 |
| daily_summaries | 日期、摘要、处理范围及版本 |
| followups | 时间窗口、事件动机、可见性、处理状态 |
| proactive_jobs | 机会去重、概率结果、预算、发送状态 |
| maintenance_jobs | 每日整理、重试、清理与迁移进度 |
| audit_logs | 管理操作、错误及删除标记，避免记录被删正文 |

群成员同时交谈时按关系主键串行更新，SQLite事务与唯一约束防止重复结算。群级主动预算独立加锁，避免不同用户并发突破上限。

## 10. 模型调用与可信边界

- 普通回复复用 AstrBot 配置的对话模型。
- 关系分析与每日整理可指定独立模型；默认关系分析一次、主回复一次，每轮调用有明确上限。
- 每日整理只处理增量，分批限制长度与并发；主动生成只在概率通过后调用。
- 分析结果使用结构化格式，包含各维度变化、原因、来源、置信度和记忆候选。
- 插件验证结构、取值和权限，低置信度不改变关系。
- 聊天原文和检索记忆都是数据，其中“忽略规则”“修改数据库”等文字不能变成插件指令。
- 用户只能通过经权限检查的工具改变自己的偏好或记忆；管理员操作需校验真实平台身份。
- 分析超时或格式错误：本轮关系不变，正常回复继续。
- 整理失败：不覆盖旧记忆，保留待重试任务。
- 记忆检索失败：本轮使用基础人设和可用上下文回复。
- 主动模块失败：停止该次发送，避免影响普通聊天。

## 11. 配置项

| 分组 | 主要配置 |
|---|---|
| 总开关 | 插件启用、群白名单、机器人角色档案标识 |
| 关系 | 初始值、单轮上限、日累计限制、置信度阈值、重复冷却 |
| 人设 | 沿用基础人设、角色主动倾向、相处描述长度 |
| 数值查询 | 是否允许用户查询本人好感度、展示维度（仅好感／四维）、是否显示数字 |
| 每日上限 | 好感每日增加/下降上限，其余维度每日增加/下降上限；填 0 为不限制（见 5.8） |
| 记忆 | 开关、检索条数、上下文预算、原始记录保留天数 |
| 每日整理 | 时区、执行时间、批大小、重试次数和退避 |
| 主动互动 | 开关、基础概率、检查周期、上限、冷却、安静时段 |
| 联系反馈 | 连续未回应降频规则、暂停与恢复规则 |

群级配置可覆盖全局默认；用户拒绝联系或记忆的偏好优先于群级配置。关系数值默认不在普通聊天公开。

## 12. 管理与运行维护

提供管理员查询入口，第一版可使用管理指令，不强制开发独立页面：

- 查看用户关系状态、数值等级、当日已用额度、相处描述、记忆来源及最近变更。
- 查看主动消息为何触发、概率结果和发送状态。
- 撤销某次错误变更，并按事件记录重算受影响状态。
- 修正记忆，重新生成受影响的描述和摘要。
- 暂停群、用户或主动模块。
- 分别重置关系、记忆，或清理全部档案。

区分管理员纠错和角色剧情事件。手动改分不虚构共同经历。大范围删除需显示明确对象和范围，避免模糊操作。

启动时进行数据库迁移、过期清理与遗漏任务补偿；重载和卸载时取消后台任务，避免重复调度。更换基础人设时保留事实，重新核对相处描述，不凭空抹掉经历。

如果存在其他记忆、关系或人设增强插件，开发及部署时检查上下文重复、结算重复和相互覆盖，并明确各自职责。

## 13. 验收标准

| 场景 | 预期结果 |
|---|---|
| 两名用户分别与机器人交流 | 形成独立关系和记忆，无串人 |
| 同用户跨群或角色交谈 | 默认档案独立 |
| 用户改昵称 | 关系与记忆连续 |
| 普通问答与重复夸奖 | 不机械加分，不可刷分 |
| 用户纠错、拒绝或未回复 | 不自动扣好感 |
| 对话发生争执后和解 | 有连续变化，保留合理转折 |
| 相同消息重复投递 | 只结算一次 |
| 工具调用或分段回复 | 按完整互动结算一次 |
| 回复或分析失败 | 不产生未完成互动的关系变更 |
| 用户刚更新称呼或边界 | 当轮即可生效 |
| 每日整理重复执行 | 无重复记忆和重复加分 |
| 机器人离线后重启 | 数据仍在，整理增量补跑 |
| 用户纠正或删除记忆 | 关联摘要和待办同步修正，不被重试恢复 |
| 普通用户查询他人档案 | 拒绝访问 |
| 用户 @机器人 查询好感度 | 返回本人数值，无模型调用，数值不变，不记为互动 |
| 类似但不明确的句子（改分、提问、查他人） | 不接管，由模型正常回复，不编造数值 |
| 关闭数值查询后发送“查看好感度” | 按普通聊天处理，不返回数值 |
| 数值落在等级边界（如 24/25、84/85） | 按区间下界归入对应等级，不出现越界等级 |
| 关闭数字展示后查询 | 只给出等级名称和相处描述，不含数字 |
| 当日好感涨幅达到配置上限 | 继续互动不再增加，数值与回复均正常，不报错 |
| 每日上限配置为 0 | 该方向不限制，超出默认 8/10 的增长仍可生效 |
| 收紧上限后已生效的历史数值 | 不回退；放宽上限也不补偿此前被截断的部分 |
| 主动消息达到上限或处于安静时段 | 不发送 |
| 同一主动机会多次检查 | 不重复抽取或重复发送 |
| 主动消息发送结果不明 | 不盲目重发 |
| 用户关闭主动联系 | 后续主动任务取消，发送前再次校验 |
| 多人同时聊天 | 身份正确、关系更新和群预算不冲突 |
| 数据中出现改分或越权指令 | 不绕过规则和权限 |
| 重载插件 | 无重复后台任务 |
| 两个用户形成不同相处方式 | 保留同一基础人设，不被统一高好感模板覆盖 |

自动验证重点为隔离、去重、权限、事务、删除传播、概率机会和调度恢复。角色连贯性另用多轮场景人工评估：观察是否保留基础人设、变化是否有依据、回忆是否真实、主动联系是否自然。

## 14. 实施顺序

1. 确认目标 AstrBot 版本、QQ适配器与基础人设来源；实现最小消息接入。
2. 完成SQLite存储、身份隔离、去重及关系事件记录。
3. 接入关系分析、数值限制与动态相处描述，验证不同对象的表现。
4. 完成即时记忆、检索、每日整理、纠错和删除。
5. 完成待跟进事件及主动互动，加入偏好、概率、冷却、预算和可靠发送。
6. 完成管理员入口、重载恢复、异常降级与多轮场景验收。

## 15. 开发前待确认项

这些项目影响接入方式或最终参数，不影响上述核心产品方向：

- 实际 AstrBot 版本与QQ接入适配器。
- 基础人设配置来源；同一实例是否运行多个角色。
- 第一版实际启用的群和管理员身份。
- 模型服务是否支持稳定结构化输出及调用预算。
- 是否启用群话题感知；关闭时主动互动只使用已有事件和关系动机。
- 默认频率、数据保留期和初始关系值是否需要调整。
- 数值等级的分档与名称是否需要调整；当前为六档（陌生/认识/熟悉/朋友/亲密/羁绊），仅作展示标签，不作为解锁条件（见 5.7）。
- 每日变化上限默认值是否需要按群调整；当前默认好感 +8／-10，其余维度 +8／-10，填 0 为不限制（见 5.8）。
- ~~用户是否需要查看具体数值~~：已确认支持。用户可查询本人好感度，默认展示数值加一句相处描述，可改为只展示描述或同时展示四维（见 5.6）。数值仍不向未查询的人公开，也不作为排行榜或刷分入口。
